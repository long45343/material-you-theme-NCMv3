## E1. 行高亮(歌曲列表)的触发方式与配色

背景:歌单页曲目行的圆角高亮目前只画在标题列容器上;修复后会横跨整行。横跨之后"什么时候出现、什么颜色"决定整体观感。

- **A. 悬浮出现 + 主题色淡染**:`rgba(主色, 0.06~0.10)` 圆角矩形,悬浮才出现。
  - 优点:动态主题感强(每一行都带主题色);与卡片 hover 语言一致。
  - 缺点:主题色偏淡(如白/浅色系预设)时行高亮对比弱。
- **B. 悬浮出现 + 中性淡灰**(MD3 onSurface 8%):
  - 优点:中性、任何主色下都可读,最接近 Google 官网列表交互。
  - 缺点:主题个性弱一些。
- **C. 常驻斑马纹**:奇偶行常驻极淡背景(4%)交替 + 悬浮加深。
  - 优点:长列表扫读友好。
  - 缺点:与网易云原生"纯列表"观感差异大;斑马纹在深色下易显脏。

## E2. 行高亮的实现路径

背景:需确认行元素是否横跨全列(虚拟列表片段有回收风险)。

- **A. 纯 CSS 上移(推荐,若 DOM 允许)**:把背景/圆角规则从标题列内层容器改挂到行元素,内层透明。
  - 优点:零 JS;不改文档结构,React 重渲染无风险。
  - 缺点:若行元素其实不横跨全宽(列是独立兄弟容器),此路不通,需回退到 B。
- **B. JS 列合并**:启动时把 专辑/喜欢/时长 列 DOM 移入标题列容器,使其同处一个圆角矩形。
  - 优点:视觉 100% 可控。
  - 缺点:动文档结构,与 React 协调成本高(需重挂守卫);虚拟列表下易碎。
- **C. 混合**:优先 A,发现步(Spec R1 步骤1)证明行不横跨时降级 B。

## E3. BetterNCM 入口按钮的处理方式

背景:行下方齿轮 = chromatic 注入的管理器入口,位置/尺寸未对齐。它是进插件管理器的唯一常规入口。

- **A. JS 搬移 + 守卫**:把按钮节点移入图标行(我们按钮旁),并入 MutationObserver 守卫,CSS 统一尺寸。
  - 优点:位置完美可控;体验与原生一致。
  - 缺点:搬移 chromatic 的节点,其更新可能改变结构(守卫幂等可兜底)。
- **B. 纯 CSS 定位**:不动 DOM,用 absolute 把它对齐到行内空位。
  - 优点:零结构风险。
  - 缺点:像素级依赖当前布局,顶栏宽度变化即错位;只能"对齐"不能"进排"。
- **C. 隐藏**:不显示入口,进管理器走其它途径。
  - 缺点:插件管理器没有其它常规入口,基本不可行(列出仅作对比)。

## E4. BNCM 按钮与我们按钮的相对顺序

- **A. 我们在左,BNCM 在右**(✉ ⚙ [我们] [BNCM]):主题按钮紧邻原生设置项,语义相近。
- **B. BNCM 在左,我们在右**(✉ ⚙ [BNCM] [我们]):我们的按钮更靠近窗口控制区,显眼。
- 优劣:A 更"收敛"(第三方按钮聚集在末端);B 让主题入口更突出。其余无实质差异。

## E5. 入口图标尺寸规格

背景:原生图标 = `cmd-icon` 字形 28px 档(视觉约 20px),徽章盒约 24~28px;我们目前 26px 盒 + 18px mask。

- **A. 完全对齐原生**:盒 28×28,mask 图标 20×20,间距与徽章一致。
  - 优点:并排时完全一致(用户诉求);实现最直接。
  - 缺点:无。
- **B. 盒对齐 28,字形放大到 22 突出一档**。
  - 优点:入口更醒目。
  - 缺点:与原生并排时 ours 显大,违和。
- **C. 保持 26/18 现状,仅修对齐**。
  - 优点:零回归风险。
  - 缺点:用户已明确"大小还是不对",此选项与诉求相悖。

## E7. 浅色表面分层方案(R4-a)

- **A. 白卡 + 阴影(现状强化)**:页面底改极浅灰(--reset-grey-0 类),卡片纯白 + elev-1。
  - 优点:最 MD3 官方(Google 家浅色即此);实现 = 改一个背景令牌。
  - 缺点:与网易云原生"全白"差异细微,提升感温和。
- **B. 微灰 surface-container 卡片**:页面纯白,卡片改极浅灰面(无阴影)。
  - 优点:层次柔和,护眼。
  - 缺点:非 MD3 主流(官方浅色用白卡+影)。
- **C. 白卡 + 影 + 主题色 2% 染面**:在 A 基础上卡片混入 2% 主色。
  - 优点:主题感最强。
  - 缺点:染色过度会显脏,需控制比例。

## E8. 播放页歌词排版方向(R4-b)

- **A. MD3 强对比**:当前行 = 主色 + 放大 1.15 倍 + 加粗;非当前 = 前景 55%;行距放宽;两侧渐隐。
  - 优点:"原插件味"的核心来源,视觉冲击最强。
  - 缺点:3.1 歌词容器类名含哈希,需结构锚点+滚动同步验证(有踩坑可能)。
- **B. 温和统一**:仅改颜色(当前行主色、其余前景 60%),不动字号。
  - 优点:零布局风险。
  - 缺点:提升有限。
- **C. 本轮不做歌词,只做播放页背景纱(已上线的渐变纱)+ 控制按钮组 pill 化**。
  - 优点:最稳。
  - 缺点:播放页仍是"3.x 味"最重的区域。
