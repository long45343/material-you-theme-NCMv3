# ROUND4-FIX-CHECKLIST — 第四轮界面视觉打磨与细节修复决策清单

本文档为针对 2026-09-08 截图排查发现的五大视觉与布局问题的详细决策规范文件。包含函数级、选择器级技术选项与决策记录，遵循决策文件先行、单题提问、即时落盘与末尾冲突一致性检查的工作流程。

---

## 一、 问题背景与排查摘要

1. **问题 1 (P0)**：底部播放条滑块在 00:01 位置时，进度条时间气泡（`.curtime-thumb`）浮动悬挂在左下角，背景虽为深红但文字为深灰，色彩对比度严重缺失（黑字在暗红底上几不可见），且非 hover 状态异常常驻遮挡侧栏歌单末项。
2. **问题 2 (P1)**：顶栏右侧功能区中，BetterNCM 音符（🎵）与调色盘（🎨）间距突增至 36px，相比周围 18~22px 的均匀间距产生明显断层视觉空洞。
3. **问题 3 (P1)**：搜索框内部放大镜图标被误删（仅余纯文字），且胶囊外部隐约存在未圆角化的方形淡蓝色边框虚影。
4. **问题 4 (P2)**：侧边栏“创建的歌单”超长名称末项在右侧边缘被生硬剪切掉半个字符，缺失标准省略号（`...`）。
5. **问题 5 (P2)**：主页横向推荐卡片与歌单封面方形卡片目前为 4~8px 原生较硬圆角，未统一至 MD3 标准 12px 胶囊/卡片圆角及漫反射阴影体系。

## 二、 决策问题清单与选项评估

### 【问题 1】播放条进度条与时间气泡 (.curtime-thumb)

#### Q1: 进度条悬浮时间气泡 (.curtime-thumb) 的显示机制与配色方案
* **影响文件与位置**：`src/styles/player.scss` (`body.material-you-theme .curtime-thumb .cmd-button`)
* **技术背景**：原生通过 `.StyledSliderContainer_smigcsb:not(.dragging):not(:hover) .thumb:not(.loading) .curtime-thumb { display: none !important; }` 控制隐藏。当前样式只写了背景为 `--colorPrimary1`，未声明文字颜色，导致深红底深灰字；且常驻未受控隐藏。
* **选项 A (推荐 - MD3 规范与严格状态联动)**：
  * **实现**：补齐前景色 `color: #ffffff !important;`（浅色模式白字，暗色模式高亮前景色）；显式增加状态守卫：仅当 slider 处于 `:hover` 或 `.dragging` 激活状态时显示，平静态强制 `display: none !important;` 彻底杜绝常驻左下角。
  * **优势**：完美解决对比度不足，文字清晰锐利；彻底解决非操作状态下气泡外溢遮挡侧边栏歌单的问题；严格对齐原生交互逻辑。
  * **劣势**：需精准匹配 slider 容器的 hover/dragging 状态。
* **选项 B (极简隐藏 - 彻底禁用时间气泡)**：
  * **实现**：声明 `.curtime-thumb { display: none !important; }`，彻底隐藏该悬浮气泡。
  * **优势**：零遮挡风险，视觉最纯净，规避任何滑块在最左端或最右端时的气泡外溢问题。
  * **劣势**：拖动进度条时无法实时从气泡查看悬浮目标时间。
* **选项 C (次级表面色常驻 - MD3 浮动卡片)**：
  * **实现**：采用 `background: var(--md-stage-surface); color: var(--colorWhite1);`，并保留常驻悬浮。
  * **优势**：背景与环境柔和融合。
  * **劣势**：仍然会在滑块位于左侧时遮挡底部歌单文字，无法根治视觉干扰。

#### Q2: 播放进度轨 (Progress Track) 的 Material You 主题色接管方案
* **影响文件与位置**：`src/styles/player.scss` (`[class*="StyledSliderContainer_"]`)
* **技术背景**：3.1 客户端进度条容器在 DOM 上动态声明了 CSS 变量 `--track-color` 与 `--track-precent`。
* **选项 A (推荐 - 原生 CSS 变量注入与轨道规格重塑)**：
  * **实现**：对 `[class*="StyledSliderContainer_"]` 强制覆写 `--track-color: var(--colorPrimary1) !important;`，将已播放部分 `.has` / `.track` 赋予主题主色，未播放背景轨使用 `rgba(var(--md-accent-color-rgb), 0.1)`，高度调整为 3px（hover 时 6px）。
  * **优势**：直接消费网易云内置的 `--track-color` 机制，性能最高，与原项目配方高度一致，浅色/深色主题均有高对比度反馈。
  * **劣势**：需覆盖 hover 展开动画样式。
* **选项 B (仅滑块 Thumb 着色，轨道保持低调原貌)**：
  * **实现**：不干预轨道背景与已播放颜色，仅将滑块 `.thumb` 设置为主题主色圆点。
  * **优势**：改动最小，风险极低。
  * **劣势**：已播放进度仍然是灰白低对比度线条，缺乏换肤整体感。
* **选项 C (原项目 2.x 固定定位绝对进度轨重构)**：
  * **实现**：完全重写进度条为 `position: fixed; bottom: calc(var(--bottombar-height) - 6px);` 并手写 `.has` 渐变。
  * **优势**：百分之百还原原项目 2.x 视觉。
  * **劣势**：DOM 结构脱节容易导致拖拽事件与热区坐标计算失效，破坏 3.1 原生滑块组件。

### 【问题 2】顶栏右侧功能区图标间距异常 (🎵 与 🎨 间距 36px)

#### Q3: 调色盘 (🎨) 与 BetterNCM 音符 (🎵) 间隙归一化实现方案
* **影响文件与位置**：`src/styles/nav.scss` (`#page_pc_main_nav .md-settings-menu-container`, `[class*="MiniModeIconBar_"]`)
* **技术背景**：当前调色盘通过 JS 作为兄弟元素挂载在 `MiniModeIconBar_` 之后，`MiniModeIconBar_` 自身具有右侧边距或内部弹性拉伸，叠加了调色盘的 `margin: 0 0 0 12px !important;`，产生 36px 巨大空隙。
* **选项 A (推荐 - 紧凑 flex 盒模型与抵消校准)**：
  * **实现**：保持纯 CSS 布局方案（严守“禁止 JS 搬移 React 管理节点”安全防线），将 `[class*="MiniModeIconBar_"]` 的 `margin-right: 0 !important; padding-right: 0 !important;` 彻底清零，并将其内部子项间距与调色盘外边距统一校准为严格的等距（如 `gap: 12px` 或计算后的 `margin-left`），使实测间隙稳定在 18~20px，与其它所有图标严格等宽。
  * **优势**：纯 CSS 解决，零运行时脚本开销，零 React 冲突与崩溃风险，极其稳定。
  * **劣势**：需要针对 3.1 真实的 DOM 树层级做一次精确的 margin/padding 归零。
* **选项 B (DOM 移入 MiniModeIconBar_ 末尾)**：
  * **实现**：修改 `src/main.js` 中的 `injectSettingsEntry`，将自定义生成的调色盘 DOM `appendChild` 进 `MiniModeIconBar_` 的子列表末尾，成为与音符并列的子元素。
  * **优势**：完全交由 `MiniModeIconBar_` 容器内部的 `gap` 统一管理，天然等距。
  * **劣势**：React 在重新协调或渲染顶栏徽章时，可能将未知的子节点强行卸载或产生协调冲突（第二轮曾因此引发崩溃）。
* **选项 C (将调色盘设为 fixed/absolute 坐标精确定位)**：
  * **实现**：利用绝对定位将调色盘强行锚定在音符右侧固定偏移处。
  * **优势**：不依赖 flex 容器盒模型计算。
  * **劣势**：当窗口缩放或徽章数量变化时容易与其他图标重叠或跑位。

### 【问题 3】搜索框放大镜图标丢失 & 外层矩形框虚影

#### Q4: 搜索框推荐封面黑块清理与放大镜图标恢复策略
* **影响文件与位置**：`src/styles/nav.scss` (`#page_pc_main_nav [class*="SearchWrapper_"]`)
* **技术背景**：commit `c07ab8d` 中把 `.cmd-input-prefix, .cmd-button` 一并隐藏，误杀了 `.cmd-input-prefix` 内部的放大镜图标 `.cmd-icon-search`。
* **选项 A (推荐 - 精确选择器排除与放大镜主题化)**：
  * **实现**：细化隐藏规则，仅针对推荐歌单封面图类名或无图标的占位块隐藏，严禁直接对 `.cmd-input-prefix` 设置 `display: none`；显式保留并放行 `.cmd-icon-search`，且赋予次级主题色 `color: rgba(var(--md-accent-color-secondary-rgb), 0.8) !important;`。
  * **优势**：精确消除封面黑块与无用按钮，100% 恢复原生放大镜图标并赋予 MD3 配色，契合原项目规范。
  * **劣势**：需要精确筛选选择器。
* **选项 B (Material Symbols 矢量放大镜重绘注入)**：
  * **实现**：将原生 input prefix 全部清空，使用 Material Symbols 官方 `search` SVG 数据直接替换或通过 CSS `mask-image` 渲染在 input 前端。
  * **优势**：图标尺寸、描边、粗细与右侧全套自定义 Material Symbols 图标（设置/消息/窗口控制）实现完全一致的视觉语言。
  * **劣势**：增加了少量 SVG 代码或 mask 规则。
* **选项 C (极简纯文字搜索胶囊)**：
  * **实现**：不恢复放大镜，保持当前仅显示提示文字的形态，仅微调文字左内边距至 16px。
  * **优势**：界面极致简约。
  * **劣势**：丢失了直观的“搜索”功能语义图标。

#### Q5: 搜索框外层矩形虚影边框消除方案
* **影响文件与位置**：`src/styles/nav.scss` (`#page_pc_main_nav [class*="SearchWrapper_"]`)
* **技术背景**：原生容器在 `SearchWrapper_` 或 input 外层声明了边框与浅色阴影。
* **选项 A (推荐 - 全层级边框与轮廓归零)**：
  * **实现**：对 `[class*="SearchWrapper_"]` 及其直接父/子容器全面声明 `border: none !important; outline: none !important; box-shadow: none !important; background-color: transparent !important;`，仅由内层的 `[class*="cmd-input-wrapper"]` 渲染 999px 胶囊背景与 focus 态高亮。
  * **优势**：彻底根除任何矩形毛边和淡蓝/浅灰虚影，视觉边缘绝对干净利落。
  * **劣势**：无。
* **选项 B (外层容器全胶囊化贴合)**：
  * **实现**：将外层容器的 `border-radius` 也同步强制设为 `999px !important;`。
  * **优势**：保持外层容器的物理几何形状一致。
  * **劣势**：若内层外层存在 1px 的内边距差，仍然会出现双层叠色边缘。
* **选项 C (为外层增加 MD3 细描边)**：
  * **实现**：将该边框规范化为 `1px solid rgba(var(--md-accent-color-rgb), 0.12)`。
  * **优势**：增加了卡片边界感。
  * **劣势**：打破了原项目搜索框无边框的扁平胶囊设计。

### 【问题 4】侧边栏歌单名称超长截断与省略号

#### Q6: 歌单长标题超长截断与省略号 (Ellipsis) 修复方案
* **影响文件与位置**：`src/styles/maintab.scss` (`[class*="PlayListItemContent_"]`)
* **技术背景**：当前设置了 `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`，但容器父级没有设置 `min-width: 0`，导致外层 flex 容器直接在边界把字模剪裁掉一半。
* **选项 A (推荐 - 健壮 flex 文本截断盒模型与安全右内边距)**：
  * **实现**：在 `[class*="PlayListItemContent_"] .background` 增加 `min-width: 0; padding-right: 14px !important;`；并对子级文字元素声明 `flex: 1 1 0%; min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`。
  * **优势**：严格遵循现代 CSS Flexbox 文本溢出规范，确保所有长歌单名称均能优雅地显示为完整字符 + “...”，绝不发生半字被切的情况。
  * **劣势**：无。
* **选项 B (微调字号至 13px + 缩小音符间距)**：
  * **实现**：将歌单名称字号从 14px 微调为 13px，并将音符图标右外边距从 10px 减小至 6px。
  * **优势**：单行可容纳更多文字内容。
  * **劣势**：字号与上方导航项（14px）出现微弱层级差异，且极长名称仍然需要 ellipsis 支撑。
* **选项 C (双行文本截断展示)**：
  * **实现**：采用 `-webkit-line-clamp: 2` 允许多行展示歌单名称。
  * **优势**：信息展示更完整。
  * **劣势**：会破坏侧边栏每一行固定 36px 胶囊高度的整齐韵律。

### 【问题 5】主页卡片与歌单封面 MD3 规范统一

#### Q7: 主内容区推荐歌单封面与横向卡片圆角及阴影策略
* **影响文件与位置**：`src/styles/overrides.scss`
* **技术背景**：主页横向卡片与推荐歌单方形封面圆角目前偏小（4~8px）。
* **选项 A (推荐 - 全面统合 MD3 标准 12px 圆角与漫反射微阴影)**：
  * **实现**：将主页所有卡片家族（横向特色卡片、推荐歌单封面 `[class*="CoverWrapper"]`、`[class*="CoverContainer"]`、榜单卡片）全部统合至 `border-radius: 12px !important; overflow: hidden;`，常态无脏边框，hover 时浮起 `--md-elev-1` 漫反射环境光。
  * **优势**：全站卡片视觉彻底形成统一的 MD3 规范，质感大幅跃升，与侧边栏、评论区、顶栏胶囊完全融为一体。
  * **劣势**：覆盖范围涉及主页多个子区域，需仔细校验图片裁剪与角标贴合。
* **选项 B (温和统一 8px 小圆角)**：
  * **实现**：仅将封面方形图统一为 8px 圆角，保留横向卡片原生设计，仅统一 hover 阴影。
  * **优势**：更接近网易云原生现代版的微圆角形态，改动幅度温和。
  * **劣势**：与侧栏、顶栏的 MD3 大圆角体系略有风格差。
* **选项 C (维持原生圆角，仅增加 hover 浮起)**：
  * **实现**：不触碰圆角几何尺寸，仅为卡片 hover 状态补充 `--md-elev-1` 浮动阴影。
  * **优势**：零图片裁剪风险。
  * **劣势**：未能实现 MD3 设计语言的全面覆盖。

## 四、 冲突与合理性检查

在实施前对已完成的 7 项决策进行全面的一致性、相互依赖性及潜在冲突分析：

1. **Q1 (时间气泡状态联动) 与 Q2 (进度轨保持现状) 的协同合理性**：
   - **一致性**：Q1 通过 CSS `:hover` 与 `.dragging` 严格限制 `.curtime-thumb` 仅在用户交互滑块时激活，并在激活时提供 `--colorPrimary1` 底色与 `#ffffff` 高对比白色文字，彻底根除左下角常驻遮挡；Q2 用户明确指出进度条在实机播放中并非灰白（截图系因位于 00:01 片头），因此不强行覆写 `--track-color` 内部变量，避免了与网易云底层进度渲染机制产生破坏性冲突。两者配合完全自洽。
   - **结论**：无冲突，方案精简有效。

2. **Q3 (顶栏 🎵 与 🎨 纯 CSS 间距归一) 与历史架构底线的兼容性**：
   - **一致性**：历史事故教训（96b51cc）实证“严禁 JS 搬移 React 节点”。Q3 严格坚持了纯 CSS 方案，不动 DOM 树，通过清除 `MiniModeIconBar_` 的冗余留白并将调色盘外边距校准归一，既解决了 36px 间距断层，又百分之百回避了 React 协调冲突与原生崩溃风险。
